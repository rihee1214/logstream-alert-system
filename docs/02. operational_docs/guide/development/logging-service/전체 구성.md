# Logging Service 구성도

![LoggingService_Architecture](./images/LoggingService구성도.drawio.svg)
# 1) 개요

- **목적**: 로그를 수집→검증→저장하는 파이프 라인.
- **실행 흐름**: 초기화(설정 로딩/플러그인 조립) → 런타임(Worker 루프) → 종료(자원 해제).

# 2) 런타임 순서(Worker 루프)

```
1) Config가 만들어낸 List<LogProcessor> 주입받음
2) List<LogProcessor>중에서 Committable요소 확인
while (true):
	1) Collector에서 메시지를 묶음으로 수집
	2) Validator/Persistence 순서로 LogProcessorPort 체인 처리
	3) 마지막에 "모든 committable에 대해" commit() 호출 → 사이클 종료
```
- **에러 처리**: 검증 실패/예외는 `LogErrorMessage`로 전환 후 같은 체인 타게 함.    

# 3) 커밋/일관성 모델(핵심만)

- **모델**: _at-least-once_ — 저장 성공 후에만 Source(예: Kafka) offset commit.
- **순서**: `Persistence → Collector.commit()` (역전 금지).

# 5) 최소 설정 키

## (1) Collector
### 0. 공통 필드

```
collector.fetch.wait.ms=5000
```
1. **collector.fetch.wait.ms** : 데이터 수집 간격
	- 데이터가 없으면 이 시간까지 블로킹 대기 후 반환합니다.
    - `0`은 non-blocking(되도록 삼가할 것), 음수는 허용하지 않음.
### 1. Kafka

```
kafka.topic=log_topic  

kafka.consumer.bootstrap.servers=localhost:9092  
kafka.consumer.group.id=logging-worker  
kafka.consumer.enable.auto.commit=false  
kafka.consumer.auto.offset.reset=earliest  
kafka.consumer.max.poll.records=100  
kafka.consumer.key.deserializer=org.apache.kafka.common.serialization.StringDeserializer  
kafka.consumer.value.deserializer=org.apache.kafka.common.serialization.StringDeserializer
```
1. **kafka.topic** : 구독할 토픽 이름. **여러 토픽은 `,`로 구분**(공백은 제거).
2. **kafka.consumer.bootstrap.servers** : 브로커 주소 리스트(`host:port` 콤마 구분).
3. **kafka.consumer.group.id** : 컨슈머 그룹 ID.
4. **kafka.consumer.enable.auto.commit** : 자동 커밋 여부. **`false` 권장**(저장 성공 시점에 수동 커밋).
5. **kafka.consumer.auto.offset.reset** : **커밋 오프셋이 없거나 범위를 벗어난 경우** 시작 위치.
    - `earliest`: 가장 오래된 위치부터 재시작(신규 그룹/재처리에 유리)
    - `latest`: 가장 새로운 위치부터(신규 그룹이 과거 로그를 건너뜀)
    - `none`: 조건 충족 시 예외 발생
6. **kafka.consumer.max.poll.records** : 한 번의 `poll()`에서 **최대 반환 레코드 수**(배치 크기).
7. **kafka.consumer.key.deserializer** : 키 역직렬화 클래스.
8. **kafka.consumer.value.deserializer** : 값 역직렬화 클래스.

> 참고/주의
> - 처리 시간이 길어 **`poll()` 호출 간 간격**이 5분(기본값)을 넘을 가능성이 있으면, 컨슈머 리밸런스가 발생할 수 있습니다. 필요 시 **컨슈머 측 속성으로 조정**하세요(**collector.fetch.wait.ms**).
> - `enable.auto.commit=false` 설정 시, **저장 성공 후에만 수동 커밋**하도록 구현되어야 합니다(중복 방지/일관성 확보).
