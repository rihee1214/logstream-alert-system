# Guide Overview

> 이 디렉토리는 각 서비스의 **설정(config)**, **개발(development)**, **기동 및 사용(usage)** 가이드를 정리한 공간입니다.  
> 신규 개발자 온보딩, 서비스 유지보수, 환경 구성 자동화 등에 있어 **일관된 기준**을 제공하는 것을 목표로 합니다.

---

## 디렉토리 구조

```
guide/  
├─┬─ config/ # 서비스별 환경 설정 및 공통 설정 가이드  
│ └── (예: application.properties 설명, 환경 변수 목록 등)  
├─┬─ development/ # 서비스별 개발 및 테스트 방법 가이드  
│ └── (예: local 개발 환경, mock 연동 방법, 개발 규칙 등)  
└─┬─ usage/ # 서비스 실행 방법 및 사용 흐름, 테스트 시나리오 등을 포함한 활용 가이드
  └── (예: 서비스 기동 이후의 사용 흐름, 테스트 시나리오 분기 구조, 외부 연동 방식, 로그 및 알림 발생 흐름 등)
```

---

## 설명

- **`config/`**  
  각 서비스 또는 공통 설정에 대한 설명을 포함합니다.  
	- 예: `application.yml`, `docker-compose.override.yml`, `configMap` 등
	- 민감 정보 제외 원칙에 따라 실제 값 대신 **형식과 목적** 중심으로 설명합니다.

- **`development/`**  
  개발자에게 필요한 **로컬 실행 방법, 테스트 구조, 디버깅 방법** 등을 문서화합니다.  
	- 예: mock 서버 호출 방식, 공통 유틸 사용 방법, traceId 테스트 전략 등
	- 코드 작성 시 **지켜야 할 가이드라인**도 포함될 수 있습니다.

- **`usage/`**  
  각 서비스 또는 시스템의 **실행 방법**, **사용 흐름**, **기능 검증 절차**, **테스트 시나리오** 등을 설명합니다.  
	- 예: 스케줄러 트리거 흐름, 외부 호출 구조, 로그 발생 및 알림 흐름 등  
	- 단순한 기동 문서를 넘어서, 운영 및 테스트 환경에서의 **실제 기능 활용 관점의 가이드**로 구성됩니다.  
	- 필요에 따라 운영 중 수동 확인 절차나 장애 대응 흐름도 포함할 수 있습니다.

---

## 참고

- 이 문서들은 프로젝트의 **운영 가능성과 유지보수성 확보**에 핵심적이며,  
  실제 코드 변경과 함께 **지속적으로 유지보수 되어야 합니다.**
- 가이드는 실무 담당자뿐 아니라 신규 팀원에게도 **첫 접점**이 되므로,  
  문서의 정확성과 최신성이 매우 중요합니다.
