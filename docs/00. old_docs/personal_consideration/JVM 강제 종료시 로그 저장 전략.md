# JVM Crash Log Strategy

## 1. 문제 인식
- 컨테이너 환경에서 JVM이 Crash가 발생했을때, 그 로그를 저장, 분석할 수 있는 공간에 이동할 필요가 존재함

## 2. 가능한 대응 전략
- 별도의 저장소(네임드 볼륨, 객체 저장소 등등)를 각 컨테이너에 마운트 시킬 수 있도록 설정하고, 거기에 로그와 core덤프가 생성되도록 한다.
```JavaOption
-XX:+HeapDumpOnOutOfMemoryError \
-XX:ErrorFile=/var/log/jvm_crash/hs_err_%p_%t.log
```

## 3. 발생 가능한 파생 문제
- 로그 파일 덮어쓰기 리스크: 동일 PID 재사용 등으로 인해 이름이 중복될 수 있음
- 컨테이너 종료 전 로그 손실: core dump 쓰기 완료 전 컨테이너 종료되는 문제

## 4. 파생 문제에 대한 가능한 대응 전략
- `hs_err_%p_%t.log` 라는 이름으로 파일 생성 되도록 java option 설정
- 로그파일, 코어 덤프가 제대로 생성되기 전에 컨테이너가 파기되지 않도록 파기 지연 설정 추가

## 5. 향후 고려사항
- 어떤 저장소를 마운트 시킬지
- 추가 솔루션 필요 여부 고려
- core 덤프와 로그가 제대로 생성되어 저장되기 적절한 컨테이너 파기 타임을 가지는지 고려
